# เอกสารจ้างทำโมเดล/อนิเมชัน — WOLD Arture

เอกสารนี้เอาไว้ **ส่งให้คนที่เราจ้าง** และใช้เป็นเกณฑ์ตรวจรับ เขียนจากข้อกำหนดจริงของโค้ดในโปรเจ็คนี้
ไม่ใช่คำแนะนำทั่วไป — ของที่ทำผิดสเปกในนี้ **เอาเข้าเกมแล้วจะไม่ขึ้น หรือขึ้นแต่ผิดที่** และแก้เองทีหลังแพงกว่าจ้างใหม่

> สรุปสั้นที่สุด: ของทุกชิ้นต้อง **ตั้งชื่อตามที่กำหนด · วางจุดกำเนิดตามที่กำหนด · ส่งเป็น `.rbxm` ·
> และ*เรา*เป็นคนอัปโหลดขึ้น Roblox เอง** ไม่ใช่ผู้รับจ้าง

## 0. กติกาข้อแรกที่พลาดกันบ่อยที่สุด — เรื่องบัญชีและสิทธิ์

| เรื่อง | กติกา | เหตุผล |
|---|---|---|
| **อนิเมชัน** | **ต้องอัปโหลดจากบัญชี/กลุ่มที่เป็นเจ้าของเกมเท่านั้น** | Roblox บล็อกอนิเมชันที่บัญชีอื่นเป็นเจ้าของ เล่นในเกมเราไม่ขึ้นเลย ต่อให้ id ถูก |
| รูปไอคอน / เดคัล | ให้ส่งไฟล์ PNG มา **เราอัปเอง** | ถ้าผู้รับจ้างอัปให้ เราได้ **Decal id** ซึ่งใส่ใน `ImageLabel.Image` แล้วไม่ขึ้น ต้องแปลงเป็น image id อีกชั้น (เจอมาแล้วทั้ง 23 ชิ้น) |
| เสียง | ส่งไฟล์มา เราอัปเอง | เสียงมีข้อจำกัดเรื่องเจ้าของเข้มกว่าทุกอย่าง |
| Mesh | ส่ง `.fbx`/`.obj` + `.blend` มา เราอัปเอง | เราต้องแก้/ส่งออกใหม่เองได้ในอนาคตโดยไม่ต้องตามตัวคนทำ |

**ห้ามเด็ดขาด:** ของที่แกะมาจากเกมอื่น · ของจาก Creator Store ที่ไม่รู้สัญญาอนุญาต · โมเดลที่ซื้อต่อมาแล้ว
สัญญาห้ามใช้เชิงพาณิชย์ — ติดโมเดอเรชันหรือโดนถอดทีหลัง เสียทั้งเงินทั้งเวลา

**ข้อตกลงที่ควรเขียนในสัญญา**
1. ลิขสิทธิ์/สิทธิ์ใช้งานตลอดชีพแบบไม่จำกัด (รวมเชิงพาณิชย์และการแก้ไขดัดแปลง) โอนมาที่เราเมื่อจ่ายครบ
2. ส่ง **ไฟล์ต้นฉบับ** ด้วยเสมอ (`.blend` / `.fbx` / `.rbxm` ที่ยังแยกชิ้น) ไม่ใช่เฉพาะไฟล์ส่งออก
3. รับรองว่าเป็นงานต้นฉบับ ไม่ละเมิดสิทธิ์ใคร และรับผิดชอบถ้ามีการเรียกร้อง
4. แก้งานตามสเปกในเอกสารนี้ได้ไม่จำกัดรอบจนผ่านเกณฑ์ตรวจรับข้อ 7 (แยกจาก "แก้เพราะเปลี่ยนใจ" ซึ่งคิดเงินเพิ่มได้)
5. ห้ามขายชิ้นงานเดียวกันซ้ำให้โปรเจ็คอื่น (ถ้าต้องการ exclusivity — ราคาจะสูงขึ้น ต้องตกลงกันแต่แรก)

## 1. กติกากลางที่ใช้กับของทุกชนิด

- **สเกลของ Roblox: 1 stud ≈ 28 ซม.** ตัวละคร R15 สูงราว 5 studs — ปั้นใน Blender ให้ 1 หน่วย = 1 stud
- **หน้า = ทิศ −Z** เสมอ (ตรงกับ `CFrame.LookVector`) กว้างตามแกน X สูงตามแกน +Y
- ส่งเป็น **`.rbxm` หนึ่งไฟล์ต่อหนึ่งชิ้น** ชื่อไฟล์ = ชื่อโมเดล
- ทุกชิ้นต้องเป็น `Model` ที่ **ตั้ง `PrimaryPart` มาแล้ว**
- ชิ้นส่วนย่อย **ตั้งชื่อให้สื่อความหมาย** (`Blade`, `Guard`, `Handle`) ห้ามเหลือ `Part`, `Part1`, `Cube.001`
- ไม่ใส่ Script / LocalScript / ModuleScript มาในโมเดล (ระบบเกมเป็นคนใส่เอง)
- **งบชิ้นส่วน/สามเหลี่ยม** เกมนี้เล่นบนมือถือด้วย: ของถือ ≤ 80 ชิ้น · ชุดเกราะ ≤ 120 ชิ้น · ยานพาหนะ ≤ 250 ชิ้น
  ถ้าเป็น MeshPart: ของถือ ≤ 1,500 tris · ชุด ≤ 4,000 tris · ยานพาหนะ ≤ 10,000 tris
- **หลีกเลี่ยง `Material` ที่ลายแรงจนกลบสี** — `CorrodedMetal` กับ `Brick` เปลี่ยนสีที่เราตั้งไปคนละสี
  ถ้าอยากได้เทา/ดำ ใช้ `Metal` `Concrete` `Slate` แล้วแต้มสนิมเป็นจุดแทน
- **`Neon` สีจางจะเบิร์นเป็นก้อนขาว** อัญมณี/แสงต้องใช้สีอิ่มกว่าที่ตาอยากได้หนึ่งขั้น และชิ้น Neon ต้องเล็ก
  นั่งอยู่ในเบ้าสีเข้ม ไม่ใช่แผ่นใหญ่
- ถ้ามี `ParticleEmitter` / `Beam` / `PointLight` ให้ส่งมาในไฟล์ `.rbxm` (ทางอื่นพามันมาด้วยไม่ได้)

## 2. อาวุธและเครื่องมือที่ถือในมือ (สกินอาวุธ · เครื่องมือ)

ปลายทาง: `ReplicatedStorage.WOLD_Skins` — **ชื่อโมเดลต้องตรงกับ id ของไอเทมเป๊ะ** เช่น `Skin_Sword_Ember`

### ผังพิกัด — ข้อที่พลาดแล้วพังทั้งหมด

> **ปลายที่ใช้งาน (คม/ปากกระบอก/ปลายคัน) อยู่ที่จุดกำเนิด (0,0,0) และด้ามยื่นไปทาง +Y
> โดย "จุดที่ฝ่ามือกำ" อยู่ที่ y = 2.0**

เกมไม่ได้ขยับโมเดลให้เข้ามือ มันเอา `PrimaryPart` ไปผูกกับมือแล้วใช้ค่าชดเชยชุดเดียวกับของเดิมทุกชิ้น
ผิดจากนี้ = ถือกลับหัว หรือกำที่ใบมีด

| ชนิด | ความยาวส่วนหลัก | การ์ด/หัว | ด้าม | หัวด้าม | กว้างสุด |
|---|---|---|---|---|---|
| ดาบ | ใบยาว 2.9–3.0 คร่อมจุดกำเนิด (y −1.45 ถึง +1.45) | y = 1.55 | y = 2.0 ยาว 0.9 | y = 2.5 | ใบกว้าง ≤ 0.55 |
| ดาบใหญ่ | ใบยาว 4.4 (y −2.2 ถึง +2.2) | y = 2.3 | y = 3.0 ยาว 1.4 | y = 3.8 | ใบกว้าง ≤ 0.85 |
| ขวาน/อีเต้อ/พลั่ว | ด้ามยาว 3.0 คร่อมจุดกำเนิด | หัวอยู่แถว y = −1.1 | y = 2.0 ยาว 0.9 | y = 2.5 | หัวกว้าง ≤ 3.0 |
| คันเบ็ด | ก้านยาว 3.2 | รอก y ≈ 1.5 | y = 2.0 | y = 2.5 | — |
| ธนู | แกนกลางที่จุดกำเนิด | ปีก y = ±1.25 ปลายปีก ±2.05 | จับที่จุดกำเนิด | — | สาย z ≈ 0.62–0.70 |
| ปืน | ลำกล้องคร่อมจุดกำเนิด | ปากกระบอก y = −0.95 | ด้าม y = 2.0 เยื้อง z = −0.22 เอียง 18° | y = 2.48 | — |
| คทา | ก้านยาว 4.0 คร่อมจุดกำเนิด | หัวคทา y = 2.25 | จับกลางก้าน | ปลอกล่าง y = −2.0 | — |
| สมุดเวท | ปกแบนคร่อมจุดกำเนิด 1.3 × 1.6 | สัน x = −0.64 | ตัวล็อก x = +0.64 | — | หนา ≤ 0.7 |

### ข้อกำหนดทางเทคนิค
- **`PrimaryPart` ต้องเป็นชิ้นที่ไม่ถูกหมุนเลย และอยู่ที่ (0,0,0) พอดี**
  ถ้าตัวหลักเป็นทรงกระบอก (ด้าม/ก้าน) ให้ทำ **แท่งสี่เหลี่ยมบางๆ ซ่อนไว้ข้างในชื่อ `Core`** แล้วตั้งอันนั้นเป็น
  `PrimaryPart` แทน — ทรงกระบอกของ Roblox วางแกนตาม X ต้องหมุน 90° เสมอ เอาไปเป็นตัวผูกแล้วอาวุธจะนอนขวางมือ
- ทุกชิ้น: `Anchored = false` · `CanCollide = false` · `CanQuery = false` · `CanTouch = false` · `Massless = true`
- เชื่อมทุกชิ้นเข้ากับ `PrimaryPart` ด้วย **`WeldConstraint`** (ไม่ใช่ `Motor6D` ไม่ใช่ `Weld`)
- **ห้ามเอาชิ้นตกแต่งไปเกาะข้างเดียวของปลายที่เรียว** ปลายจะดูเบ้ไปข้างหนึ่งทันที
- ถ้าอาวุธมีไฟ ให้ใส่ `PointLight` ที่ `Range ≤ 10` `Brightness ≤ 2` และปิด `Shadows`

## 3. ชุดเกราะ / ชุดแฟชั่น

ปลายทาง: `workspace.Model_Item` — ชื่อโมเดลตามที่เรากำหนด เช่น `Fashion_Royal_GoldKit`

โครงสร้างบังคับ (ระบบสวมใส่จับคู่ด้วย**ชื่อ** ไม่ได้วัดตำแหน่งเอง):

```
Fashion_XXXKit            (Model, ต้องมี PrimaryPart)
├── Root                  (Part โปร่งใส ที่จุดกำเนิด — ระบบใช้ชิ้นนี้วัดสเกล **ขาดไม่ได้**)
├── Armor_Head            (Model — ชิ้นส่วนที่สวมหัว)
├── Armor_UpperTorso      (Model)
├── Armor_LowerTorso      (Model)
├── Armor_RightUpperArm   (Model)      ... ครบทุกข้อต่อที่ต้องการ
├── Armor_LeftLowerLeg    (Model)
└── Armor_Cape            (Model — ชื่อที่ไม่ตรงข้อต่อ R15 = ของตกแต่ง ระบบจะเชื่อมไว้กับลำตัวให้)
```

- ชื่อข้อต่อ R15 ที่ใช้ได้: `Head` `UpperTorso` `LowerTorso` `RightUpperArm` `RightLowerArm` `RightHand`
  `LeftUpperArm` `LeftLowerArm` `LeftHand` `RightUpperLeg` `RightLowerLeg` `RightFoot` `LeftUpperLeg`
  `LeftLowerLeg` `LeftFoot`
- **ปั้นทับบนหุ่น R15 มาตรฐานขนาด 1.0** ระบบจะย่อ/ขยายตามตัวผู้เล่นเอง (ตัวละครโตขึ้นตามเลเวล)
- **ชิ้นที่ทาบหัวห้ามต่ำกว่า y = 0.30 ของหัว** ไม่งั้นไปบังหน้า (ตา/ปากเป็นเดคัลบนหัว)
- **เกราะขาห้ามเกิน ~1.15 เท่าของขา** ขาสองข้างของ R15 ชิดกันที่ x = 0 เกินกว่านี้จะเชื่อมเป็นก้อนเดียว
- ไหล่: ใช้**แผ่นเหลี่ยมซ้อนกัน 3 ชั้นเอียงออกทีละชั้น** ไม่ใช่ลูกบอลใบใหญ่ (มันกลืนแขนทั้งท่อน)
- ผ้าคลุม: **ต้องมีริมผ้าสีเข้มกว่าที่ขอบทั้งสองข้าง** ไม่งั้นอ่านเป็นแผ่นป้ายแขวนหลัง และ**สีผ้าต้องต่างจากสีเกราะ**
- ไม่ต้องใส่สีพิเศษอะไรเพิ่ม — เราไม่ทาสีทับแล้ว ชุดจะแสดงสีตามที่ปั้นมาเป๊ะ

## 4. ออร่า (เอฟเฟกต์ลอยรอบตัว)

ปลายทาง: `ReplicatedStorage.WOLD_Effects` — ชื่อโมเดล = id ของไอเทม เช่น `Aura_Ember`

- ต้องมี **`PrimaryPart`** (ชิ้นเล็ก โปร่งใส ที่จุดกำเนิด) ระบบเอาชิ้นนี้ผูกกับกลางตัวผู้เล่น
- ระบบจะวางจุดกำเนิดไว้ที่ **กลางลำตัว เยื้องลง 0.5 stud** ให้ออกแบบโดยคิดว่าจุด (0,0,0) คือสะดือผู้เล่น
- ทุกชิ้น `CanCollide = false` และควร `Massless = true`
- **เอฟเฟกต์ต้องกระจายออกรอบตัวเป็นรัศมี ไม่ใช่เป็นเส้น** — ถ้าใช้ `ParticleEmitter` ให้ตั้ง
  `Shape = Sphere` + `ShapeStyle = Volume` + `ShapeInOut = Outward`
  (**ห้ามใช้ `Cylinder`** แกนของมันอยู่ตามแกน X ของพาร์ท เคยทำให้ออร่าออกมาเป็นเส้นแบนเส้นเดียวมาแล้ว)
- งบอนุภาค: รวมทุกชั้นแล้ว `Rate` ไม่เกิน ~120/วินาที และเม็ดต้องโปร่ง (`Transparency ≥ 0.6` สำหรับชั้นหมอก)
  — ความฟุ้งมาจากเม็ดโปร่งซ้อนกัน ไม่ใช่เม็ดทึบ
- ส่งเป็น `.rbxm` เท่านั้น (ทางอื่นพา ParticleEmitter มาไม่ได้)

## 5. ยานพาหนะ (รถ · เรือ · เรือเหาะ)

**สำคัญมาก: เราจ้างทำ "เปลือกนอก" อย่างเดียว ไม่ใช่รถที่ขับได้**

ตัวถังที่ชนได้ ล้อ เบาะนั่ง และฟิสิกส์ทั้งหมด **โค้ดของเราสร้างเอง** และค่าทุกตัวเป็นผลของการไล่บั๊กมานาน
(ล้อส่าย · เรือดีดขึ้นฟ้า · เรือเหาะเกยหิน) ถ้าส่งรถที่ขับได้มาเราใช้ไม่ได้และต้องรื้อทิ้ง

สิ่งที่ต้องส่ง: `Model` เปลือกนอกที่จะถูก**เชื่อมทับ**ลงบนโครงที่โค้ดสร้าง

| ชนิด | กล่องตัวถังที่ต้องครอบให้พอดี (X × Y × Z) | หมายเหตุ |
|---|---|---|
| รถไอน้ำ | 6.6 × 2.6 × 14 | กึ่งกลางล้ออยู่สูงจากพื้น 1.9 · ล้อรัศมี 2.8 (เว้นซุ้มล้อให้พอ) |
| เรือ | 12 × 4 × 30 | ท้องเรือต้องอยู่ต่ำกว่าจุดกำเนิด |
| เรือเหาะ | 10 × 4 × 26 | นี่คือ**ตัวกระเช้า** ส่วนบอลลูนเป็นของตกแต่งไร้มวลที่อยู่เหนือขึ้นไป |

- **หน้า = −Z** · ฐานอยู่ที่ y = 0 · กึ่งกลางที่ x = 0
- ทุกชิ้นของเปลือกต้อง `Massless = true` และ `CanCollide = false` (มวลและการชนอยู่ที่ตัวถังของโค้ด)
- **ตั้งชื่อจุดยึดให้ชัด** ถ้าจะให้ของหมุนได้: ล้อแต่ละล้อเป็น `Model` ชื่อ `Wheel_FL` `Wheel_FR` `Wheel_RL` `Wheel_RR`
  ใบพัด/กังหันเป็น `Model` ชื่อ `Propeller` / `PaddleWheel_L` / `PaddleWheel_R` และ**ในแต่ละอันมีพาร์ทชื่อ `Axis`**
  วางที่แกนหมุนจริง (โค้ดหมุนรอบแกน X ของชิ้นนั้น)
- ที่นั่ง: อย่าใส่ `Seat`/`VehicleSeat` มา แต่ให้วาง **พาร์ทโปร่งใสชื่อ `SeatMark_Driver`, `SeatMark_1`, `SeatMark_2`…**
  ตรงตำแหน่งที่ควรนั่ง เราจะเอาไปวางเบาะจริงเอง
- ธีม: **สตีมพังก์ยุคไอน้ำ** — ทองเหลือง เหล็กหมุด ไม้ หม้อไอน้ำ เฟือง ท่อ มาตรวัด ปล่องควัน

## 6. อนิเมชัน

- **R15 เท่านั้น** ทำบนหุ่น R15 มาตรฐานของ Roblox
- ส่งเป็น **`.fbx`** (หรือไฟล์ `.rbxm` ของ `KeyframeSequence`) + วิดีโอพรีวิว — **อย่าอัปโหลดเอง** เราอัปจากบัญชีเจ้าของเกม
- **ท่าต่อสู้/ท่าถือของ ให้ขยับเฉพาะแขนกับลำตัว ห้ามใส่คีย์ที่ขา** เพราะท่าเดิน/วิ่งของเกมต้องคุมขาต่อไปได้
  ขณะที่ท่านั้นคุมครึ่งบน (ผู้เล่นต้องเดินไปถือการ์ดไปได้)
- **Roblox ไม่มี root motion** — อนิเมชันไม่ขยับตัวละคร การพุ่ง/กระโดด/สไลด์เป็นหน้าที่ของโค้ด
  ให้ทำท่าโดยสมมติว่าตัวละครอยู่กับที่
- ต้องส่ง **ตารางเวลา (timing sheet)** มาด้วย: จังหวะไหนคือ "เริ่มเหวี่ยง / โดนเป้า / จบท่า" เป็นวินาที
  เพราะโค้ดฝั่งเรายิงดาเมจและเสียงตามเวลาที่กำหนดไว้ ถ้าเวลาไม่ตรง เสียงจะดังตอนดาบยังไม่ถึง
- ถ้ามี "จังหวะสำคัญ" ในท่า ให้ใส่ **`KeyframeMarker`** ชื่อที่เราตกลงกัน (เช่น `Hit`, `Beat`) จะได้ผูกเสียงตรงจังหวะได้
- อาวุธถือด้วย**มือขวา**เสมอ (ดาบถูกผูกกับ `RightHand`) ถ้าเป็นท่าสองมือ **มือซ้ายต้องข้ามมาจับด้ามฝั่งขวา**
  ไม่ใช่มาบรรจบกันที่แนวกลางลำตัว — ตรงกลางไม่มีอะไรให้จับ
- ความยาวคลิป/ลำดับความสำคัญ (`AnimationPriority`) เราจะระบุให้เป็นรายท่า

## 7. เกณฑ์ตรวจรับ (ผ่านครบถึงจ่าย)

เราตรวจด้วยสคริปต์ ไม่ได้ดูด้วยตาอย่างเดียว ข้อที่ตรวจ:

1. ไฟล์เป็น `.rbxm` ชื่อตรงตามที่กำหนด เปิดแล้วได้ `Model` หนึ่งตัว
2. `PrimaryPart` มีจริง **อยู่ที่ (0,0,0) และไม่ถูกหมุน**
3. ของถือ: ทุกชิ้น `Anchored = false` และเชื่อมเข้ากับ `PrimaryPart` แล้ว
4. **กล่องขอบ (bounding box) ต่างจากของเดิมที่มันไปแทนไม่เกิน ±15%** และจุดกำเนิดเยื้องไม่เกิน 0.3 stud
5. จำนวนชิ้น/สามเหลี่ยม ไม่เกินงบในข้อ 1
6. ไม่มี Script ใดๆ ติดมา · ไม่มีชิ้นชื่อ `Part` ลอยอยู่
7. ชุดเกราะ: มีชิ้น `Root` และมีลูกเป็น `Model` ชื่อ `Armor_*` ครบตามรายการที่สั่ง
8. เอาเข้าเกมจริงแล้ว **ถือ/สวมได้โดยไม่ต้องแก้อะไรเลย** — นี่คือเกณฑ์สุดท้าย

**วิธีจ่ายที่แนะนำ:** มัดจำ 30% → ส่งงานชิ้นแรกหนึ่งชิ้นให้ตรวจก่อน (pilot) → ผ่านแล้วค่อยทำที่เหลือ →
จ่ายส่วนที่เหลือเมื่อผ่านเกณฑ์ข้อ 8 ครบทุกชิ้น · การทำ pilot ชิ้นเดียวก่อนคุ้มมาก เพราะถ้าเขาไม่เข้าใจผังพิกัด
เราจะรู้ตั้งแต่ชิ้นแรก ไม่ใช่ตอนได้ของมา 20 ชิ้นแล้วผิดหมดทุกชิ้น

## 8. ของที่ต้องส่งให้ผู้รับจ้างพร้อมใบสั่งงาน

1. เอกสารนี้
2. **ไฟล์ `.rbxm` ของ "ของเดิม" ที่ชิ้นใหม่จะไปแทน** — ให้เขาเปิดดูขนาดและจุดกำเนิดของจริง
   มีประโยชน์กว่าตัวเลขในตารางมาก (ของเดิมทุกชิ้นสร้างจากโค้ดใน `WeaponPrefabs.server.lua`
   และต้นฉบับอยู่ที่โปรเจ็ค `WOLD-Models` โฟลเดอร์ `export/`)
3. ภาพอ้างอิง/มู้ดบอร์ดของชิ้นนั้น
4. รายชื่อชิ้นงานพร้อม **ชื่อโมเดลที่ต้องใช้เป๊ะๆ** (ตรงกับ id ไอเทมในเกม)
5. ธีมรวมของเกม: **ยุคกลาง + แฟนตาซี/เวทมนตร์ + สตีมพังก์ (เครื่องจักรไอน้ำ)**
