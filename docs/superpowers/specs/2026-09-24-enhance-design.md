# ตีบวกอาวุธ +1 ถึง +10 ที่ช่างตีเหล็ก — ดีไซน์

วันที่ 2026-09-24 · ระบบที่ 3 จาก 4 ของชุด "MMO เพิ่มเติม" (ผู้ใช้สั่งทำก่อนระบบที่ 2 แชทข้ามเซิร์ฟ)

## ทำไมต้องมี

ได้อาวุธมาแล้วก็จบ ไม่มีเป้าหมายระยะยาว · ตีบวกให้เป้าหมาย และดูดซิลเวอร์/แร่/ของผิดกฎหมายออกจากระบบเศรษฐกิจ

## สิ่งที่ผู้ใช้กำหนด

| ข้อ | ค่า |
|---|---|
| ที่ทำ | **ช่างตีเหล็ก (แบรนน็อค)** — แท็บใหม่ "ตีบวก" ในหน้าต่างคราฟเดิม |
| ขั้น | +1 ถึง +10 |
| ของที่ใช้ | **เพิ่มขึ้นทุกขั้น เน้นแร่ + ของผิดกฎหมาย + ซิลเวอร์หลักพัน** (ตารางข้างล่าง ผู้ใช้อนุมัติแล้ว) |
| โบนัสดาเมจ | **+1 ถึง +5 ขั้นละ 3% · +6 ถึง +10 ขั้นละ 8%** (+10 = +55%) |
| โอกาสสำเร็จ | 100 / 95 / 90 / 80 / 70 / 60 / 50 / 40 / 30 / 20 % (ขั้นที่กำลังตีขึ้นไป) |
| ตีแตก | **เสียความคงทน 10% ของค่าเต็ม** ขั้นไม่ลด อาวุธไม่หาย ความคงทนต่ำสุด 1 |
| ตีได้ | **อาวุธต่อสู้เท่านั้น**: Sword Bow Staff Spellbook Greatsword Shield Pistol |
| วัสดุหาย | ทุกครั้งที่กดตี ไม่ว่าสำเร็จหรือแตก |

## องค์ประกอบ

### `ReplicatedStorage/EnhanceConfig.lua` (ใหม่ · ข้อมูลล้วน)
- `Weapons = { Sword = true, ... }` · `MaxLevel = 10` · `FailDurabilityFraction = 0.10` · `Seconds = 4` (ความยาวแถบ ผมตั้งเอง ปรับได้)
- `Levels[n] = { chance, bonus, cost = { [itemId] = n } }` — `bonus` = ดาเมจรวมที่ขั้นนั้น (0.03, 0.06 … 0.15, 0.23 … 0.55)
- `EnhanceConfig.Bonus(level) -> number` · `EnhanceConfig.LevelOf(meta) -> 0..10`

### ขั้นอยู่บนตัวอาวุธ
`meta.enhance = n` บนช่องอาวุธ (ที่เดียวกับ `meta.skin`) — เดินทางไปกับอาวุธทุกที่ที่ meta เดินทาง (สวม/ถอด/เทรด/คลัง/เมล)
`ItemCatalog.DisplayName` ต่อท้าย `+n` (รวมกับชื่อสกินได้: "ดาบ +7 (เปลวเพลิง)")

### ดาเมจ
- `ClassPerks.DamageFor(attacker, amount)` คือจุดที่การตีปกติทั้งสองทางผ่าน (ระยะประชิด + กระสุน) → คูณ `1 + Bonus(level ของอาวุธที่ถืออยู่)`
- สกิล Q ไม่ผ่าน DamageFor (`WeaponSkills.damageAndScore` + ทางดาเมจบอทในสนาม) → คูณตัวเดียวกันที่นั่นด้วย
- อ่านขั้นจาก `Inventory.EquippedWeapon(player)` → `entry.meta`

### ฝั่งเซิร์ฟเวอร์ — อยู่ใน `Crafting.server.lua`
เพราะมันถือ "ยืนหน้าช่างตีเหล็กอยู่ไหม" (`nearSmith`) · นับ/หักวัสดุ (`countMaterial`/`takeMaterial`) · และภาพหน้าต่าง (`snapshot`) อยู่แล้ว
- snapshot เพิ่ม `enhance = { fee..., rows = { { slot, id, name, level, next = { chance, cost[], affordable } } } }` เฉพาะตอนยืนที่ช่างตีเหล็ก (ไม่ใช่สถานีครัว)
  รายการ = อาวุธต่อสู้ในกระเป๋า **และอาวุธที่ถืออยู่** (ช่อง `slot = "equipped"`)
- remote ใหม่ `RequestEnhance(slot)`:
  1. อยู่ใกล้ช่างตีเหล็ก · ช่องนั้นมีอาวุธใน `EnhanceConfig.Weapons` · ขั้น < 10 · ช่างตีเหล็กว่าง (ล็อก `Busy` ตัวเดียวกับคราฟ)
  2. มีวัสดุครบ (รวม Silver) → หักทั้งหมด
  3. **ยื่นอาวุธให้ช่าง**: เอาอาวุธออกจากกระเป๋า/มือ ไปอยู่ในงานที่ค้าง · แถบเวลาเดินเหมือนคราฟ (**ผู้ใช้สั่ง: ตีแล้วรอรู้ผล เหมือนการคราฟ**) `EnhanceConfig.Seconds`
  4. ครบเวลา ทอย `chance` → สำเร็จ: `meta.enhance += 1` · แตก: ความคงทน `-= ceil(max × 10%)` ต่ำสุด 1
  5. **คืนอาวุธ**: ใส่กระเป๋า → ไม่มีที่ก็ล้นเข้าคลังตามกติกาเดิม → ยังไม่ได้ (หรือผู้เล่นออกเกมไปแล้ว) ส่ง `Mail.Send` ถึงตัวเอง — อาวุธไม่มีทางหาย
  6. แจ้งผล + ส่ง snapshot ใหม่ · `ProfileAccess.Flush`
- ทำไมต้องเอาอาวุธออกจากกระเป๋าระหว่างรอ: ถ้าปล่อยไว้ ผู้เล่นย้าย/ทิ้ง/เทรดได้ระหว่างแถบเดิน แล้วตอนจบจะไม่รู้ว่าต้องบวกชิ้นไหน

### UI — `CraftGui` + `CraftController`
- `CraftConfig.Tabs` เพิ่ม `{ id = "enhance", name = "ตีบวก" }` (ไม่มี station = โชว์เฉพาะช่างตีเหล็ก)
- แท็บนี้วาดแถวคนละแบบกับสูตร: ไอคอนอาวุธ · ชื่อ + ขั้นปัจจุบัน → ขั้นถัดไป · โบนัสดาเมจ · โอกาส% · วัสดุพร้อมจำนวนที่มี/ต้องใช้ (ขาด = สีแดง) · ปุ่ม "ตี" (หรี่เมื่อวัสดุไม่พอ / "+10 สูงสุดแล้ว")

## กรณีผิดพลาด
- ช่องเปลี่ยนระหว่างส่งคำขอ (ย้าย/ทิ้งอาวุธ) → ตรวจช่องใหม่ฝั่งเซิร์ฟเวอร์ทุกครั้ง ไม่เชื่อสิ่งที่ไคลเอนต์ส่ง
- ไคลเอนต์ส่ง slot เป็นค่าแปลก (ตาราง/NaN/นอกช่วง) → `state.slots[x]` เป็น nil → ปฏิเสธ
- อาวุธไม่มีความคงทน (`maxDurability` nil) → ตีแตกแล้วไม่เสียอะไร (ไม่มีอาวุธต่อสู้แบบนั้นตอนนี้)
