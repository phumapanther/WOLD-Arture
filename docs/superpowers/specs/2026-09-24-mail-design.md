# ระบบเมล (กล่องจดหมายในหินเวทสื่อสาร) — ดีไซน์

วันที่ 2026-09-24 · ระบบที่ 1 จาก 4 ของชุด "MMO เพิ่มเติม"
(ลำดับที่ผู้ใช้เลือก: **เมล → แชท/ประกาศข้ามเซิร์ฟ → ตีบวก → ความสำเร็จ/ฉายา**)

## ทำไมต้องมี

ตอนนี้มีสามที่ที่พังด้วยเหตุผลเดียวกัน คือเกมไม่มีทางส่งของไปถึงคนที่ไม่ได้ยืนอยู่ในเซิร์ฟนี้
1. **บอสโลก** — `WorldBoss.payout` ข้ามคนที่ออกจากเกมไปแล้ว รางวัลหาย (คอมเมนต์ในโค้ดเขียนไว้ว่า "วันไหนมีระบบเมล ให้เติมตรงนี้")
2. **สนาม PVP** — ต้องมีคิว DataStore ของตัวเอง (`arenareward_<userId>`) ซึ่งต้องล้างคิวก่อนแล้วค่อยจ่าย ถ้าเซิร์ฟล่มระหว่างสองขั้นนี้ รางวัลหาย
3. **แอดมิน** — ชดเชยของให้คนที่ออฟไลน์ไม่ได้

บวกความต้องการใหม่ **ผู้เล่นส่งของหาเพื่อนได้** รวมถึงเพื่อนที่ออฟไลน์หรือเล่นอยู่อีกเซิร์ฟ

## สิ่งที่ผู้ใช้กำหนด

| ข้อ | ค่า |
|---|---|
| ที่อยู่ของ UI | **หน้าเมนูหนึ่งในหินเวทสื่อสาร** (`SocialGui` กด P) เหมือนหน้าเพื่อน แชท ตลาด |
| ใครส่งได้ | ระบบ · แอดมิน · **ผู้เล่นส่งหาคนในรายชื่อสหายเท่านั้น** |
| ค่าส่ง (ผู้เล่น) | **500 ซิลเวอร์ต่อฉบับ** |
| แนบได้ (ผู้เล่น) | **ของ 1 ช่อง** · **แนบเงินไม่ได้** |
| ส่งไม่ได้ | ของผิดกฎหมาย (**สารเคมี เฟือง แบบแปลน** — ถ่านหินส่งได้เพราะขุดได้) · ไอเทมที่กดใช้ได้ทุกชนิด · ของที่คราฟได้ทุกชิ้น · เหรียญค้อนแตก (`Insignia`) · ซิลเวอร์ |
| หมดอายุ | **ไม่หมดอายุ** |
| ขนาดกล่อง | **50 ฉบับ** |
| ที่เก็บ | **`ProfileStore:MessageAsync`** (ทาง B) |

ข้อห้ามที่มีอยู่แล้วในเกมและใช้ต่อ: ของประจำตำแหน่ง (`bound`) กับกุญแจพาหนะ (`kind == "key"`) ส่งไม่ได้

เมลจาก**ระบบและแอดมิน**ไม่ติดข้อห้ามข้างบนทั้งหมด แนบของได้หลายชิ้น แนบเงินและ EXP ได้

## ทำไมเป็น MessageAsync

`ProfileStore:MessageAsync(key, message)` ส่งข้อความเข้าโปรไฟล์ที่เจ้าของออฟไลน์อยู่ หรือเปิดเซสชันอยู่ที่อีกเซิร์ฟก็ได้
ข้อความจะไปถึงตัวรับที่ผูกด้วย `profile:MessageHandler(fn)` บนเซิร์ฟที่ถือเซสชัน

- **ของไม่หายและไม่ซ้ำ:** ตัวรับย้ายเมลลง `profile.Data.Mail` แล้วเรียก `processed()` ทั้งสองอย่างถูกเซฟพร้อมกันในโปรไฟล์ก้อนเดียว
  การกดรับก็ย้ายของจาก `Data.Mail` ไปกระเป๋าในโปรไฟล์ก้อนเดียวกัน ไม่มีช่วงที่ของอยู่สองที่หรือไม่อยู่ที่ไหนเลย
- **เรียกได้จากทุกเพลส** รวมถึงเซิร์ฟสนาม ซึ่งห้ามเปิดเซสชันโปรไฟล์ (ดู CLAUDE.md หัวข้อ PVP) — `MessageAsync` ไม่ต้องเปิดเซสชัน
- ข้อความที่ยังไม่ `processed()` ProfileStore เก็บค้างไว้ในโปรไฟล์เอง (เพดาน 1,000 ของไลบรารี)

**สิ่งที่ยอมแลก**
- เมลไม่ถึงทันที ต้องรอรอบอัตโนมัติของ ProfileStore (สิบกว่าวินาที) ตอนผู้รับออนไลน์
- ตอนกดส่ง ระบบไม่รู้ว่ากล่องผู้รับเต็มหรือยัง → **กล่องเต็มแล้ว เมลที่มาใหม่จะรอคิวอยู่** แล้วขึ้นในกล่องเมื่อมีช่องว่าง
  ไม่มีอะไรหาย แต่**ค่าส่งไม่คืน** (ผู้ใช้รับทราบแล้วตอนเลือกทาง B)

## องค์ประกอบ

### `ReplicatedStorage/MailConfig.lua` (ใหม่)
ตัวเลขทั้งหมด: `FeeItem = "Silver"` · `Fee = 500` · `BoxSize = 50` · `PlayerAttachSlots = 1`
· `Contraband = { Chemical = true, GearSpare = true, Blueprint = true, Insignia = true, Silver = true }`
· ความยาวหัวข้อ/ข้อความสูงสุด

### `ItemCatalog.IsMailable(id)` (เพิ่มในไฟล์เดิม ข้าง `IsStorable`)
ด่านเดียวที่ตัดสินว่าผู้เล่นส่งของชิ้นนี้ทางเมลได้ไหม — false เมื่อ:
ไม่มีในแคตตาล็อก · `bound` · `kind == "key"` · มี `use` · อยู่ใน `CraftableOutput` · อยู่ใน `MailConfig.Contraband`
ปุ่มฝั่งไคลเอนต์กับเซิร์ฟเวอร์ถามตัวเดียวกัน (ทรงเดียวกับ `IsBound` ที่กันปุ่ม "ให้")

### `ServerScriptService/Mail.lua` (ใหม่ · โมดูล)
- `Mail.Send(toUserId, letter) -> ok` — ประทับ `id` (GUID) และ `at` แล้วเรียก `MessageAsync("Player_" .. toUserId, letter)`
  ใช้ `ProfileStore.New("WOLD_PlayerProfile_v1")` ชื่อเดียวกับ `PlayerProfile.server` ห่อ `pcall`
- `Mail.Attach(profile)` — ผูก `MessageHandler` ให้โปรไฟล์ที่เพิ่งเปิด เรียกจาก `PlayerProfile.server` ตอนเปิดเซสชันเสร็จ
  - กล่องยังไม่เต็ม → ใส่ลง `Data.Mail` แล้ว `processed()`
  - กล่องเต็ม → **เก็บ `(letter, processed)` ไว้ในคิวในหน่วยความจำ** ไม่เรียก `processed()` · ทุกครั้งที่กล่องมีช่องว่าง (รับ/ลบ) ดึงจากคิวนี้เข้ากล่อง
    (ไลบรารีเรียกตัวรับครั้งเดียวต่อข้อความต่อเซสชัน จึงต้องจำ callback ไว้เอง · เซิร์ฟปิดก่อนได้ช่อง = ข้อความยังค้างใน ProfileStore แล้วมาใหม่รอบหน้า)
- `Mail.List(player)` · `Mail.Claim(player, letterId)` · `Mail.Delete(player, letterId)` · `Mail.Unread(player)`

### รูปทรงของเมลหนึ่งฉบับ
```
{ id, at, from = userId|0, fromName, subject, body,
  items = { {id, count, meta?}, ... },   -- ผู้เล่น: ไม่เกิน 1 รายการ
  gold = n?, exp = n?,                   -- ระบบ/แอดมินเท่านั้น
  claimed = bool, read = bool }
```
`from = 0` = ระบบ

### `ServerScriptService/PlayerMail.server.lua` (ใหม่ · remote)
- **ส่ง** `(toUserId, slot, count, subject, body)` ตามลำดับ:
  1. ผู้รับอยู่ใน `Friends.Get(player).friends` (ด่านเดียวกับนกพิราบ/ชวนตี้)
  2. ของในช่องนั้นผ่าน `IsMailable` และมีครบจำนวน
  3. มีซิลเวอร์ ≥ 500
  4. หักของและซิลเวอร์ออกจากกระเป๋า
  5. `Mail.Send` — **ส่งไม่สำเร็จ = คืนทั้งของและซิลเวอร์** แล้วแจ้งผู้เล่น
- **รับ** `(letterId)`: `HasRoomFor` ของทุกชิ้นในฉบับ → ไม่พอก็ปฏิเสธพร้อมเหตุผล เมลยังอยู่ → พอก็ใส่ของ + เงิน + EXP แล้วตั้ง `claimed`
- **ลบ** `(letterId)`: ลบได้เมื่อ `claimed` หรือไม่มีของแนบ (กันเผลอกดลบรางวัลทิ้ง)
- ส่งภาพกล่องใหม่ให้ไคลเอนต์ทุกครั้งที่กล่องเปลี่ยน · แอตทริบิวต์ `WOLD_MailUnread` บนตัว Player ให้จุดแดง

### UI
- `SocialGui` เพิ่มหน้า **"กล่องจดหมาย"** ในเมนูหน้าแรกของหินเวท: รายการเมล (ผู้ส่ง หัวข้อ ไอคอนของแนบผ่าน `ItemIcon`) · เปิดอ่าน · ปุ่มรับ · ปุ่มลบ
- หน้ารายชื่อสหาย เพิ่มปุ่ม **"ส่งของ"** ที่แถวเพื่อน (ข้างปุ่มชวนตี้) → เลือกของ 1 ช่องจากกระเป๋า (ช่องที่ `IsMailable` เป็น false หรี่ไว้กดไม่ได้) + จำนวน + ข้อความ + ขึ้นค่าส่ง 500 ซิลเวอร์ให้เห็นก่อนกด
- ตัวเลขแดงบนไทล์กล่องจดหมายในหน้าแรกของหินเวท + แจ้งเตือนในฟีดตอนเมลเข้า (ปุ่มหินเวทบน HUD มีเฉพาะจอสัมผัส จึงไม่ใช่ที่เดียวที่ทุกคนเห็น)

## ย้ายระบบเดิมมาใช้เมล

| ที่ | เดิม | ใหม่ |
|---|---|---|
| `WorldBoss.payout` | จ่ายตรงเข้ากระเป๋า ข้ามคนที่ออฟไลน์ · กระเป๋าเต็ม = ของหาย | **ทุกคนที่ติดอันดับได้เมล** ฉบับเดียวรวมเงิน/EXP/ของ/ไม้สุดท้าย |
| `ArenaRewards` → `PvpRewards.server` | คิว `arenareward_` ล้างก่อนจ่าย | สนามเรียก `Mail.Send` ตรง · `PvpRewards` เหลือหน้าที่ **อ่านคิวเก่าให้หมด** (ของที่ค้างก่อนอัปเดต) แล้วเลิกใช้ |
| แอดมิน | — | `/mail <ชื่อ> <ไอเทม> [จำนวน]` ใช้ `GetUserIdFromNameAsync` ส่งถึงคนออฟไลน์ได้ (ทรงเดียวกับ `/givevip` แบบระบุชื่อ) |

## กรณีผิดพลาด

- `MessageAsync` ล้มเหลว (DataStore ล่ม) → ผู้เล่น: คืนของ+ค่าส่ง · ระบบ: `warn` พร้อม userId และสิ่งที่จะส่ง ให้แอดมินส่งซ้ำได้
- ผู้รับเลิกเป็นเพื่อนหลังเมลส่งไปแล้ว → เมลยังไปถึง (ส่งตอนที่ยังเป็นเพื่อน)
- ของในแคตตาล็อกถูกถอดออกหลังเมลค้างอยู่ → รับได้เฉพาะส่วนที่ยังมี ส่วนที่หายแจ้งผู้เล่น ไม่ทำให้ทั้งฉบับติด
- ส่งหาตัวเอง → ปฏิเสธ (ไม่ได้อยู่ในรายชื่อสหายของตัวเองอยู่แล้ว)

## การทดสอบ

เทสในเพลส (`tests/mail_test.lua` ผ่านช่องเทส BindableFunction แบบ `QuestTest`/`IslandTest` เพราะ sandbox ของ `execute_luau` ได้สำเนาโมดูลใหม่):
- `IsMailable`: แร่/ไม้ = true · ยา/อาหาร/หีบ/ดาบใหญ่/สารเคมี/ซิลเวอร์/Insignia/กุญแจ/ตะหลิว = false
- ส่งแล้ว `MessageAsync` ล้มเหลว (จำลอง) → ของและซิลเวอร์กลับมาครบ
- รับตอนกระเป๋าเต็ม → ปฏิเสธ เมลยังอยู่ ไม่ได้ `claimed`
- กล่อง 50 ฉบับ + ข้อความใหม่ → ค้างในคิว · ลบหนึ่งฉบับ → ดึงเข้ากล่อง
- ลบเมลที่ยังไม่รับของ → ปฏิเสธ

**ทดสอบได้หลัง publish เท่านั้น:** ส่งถึงคนออฟไลน์จริง · ส่งข้ามเซิร์ฟ · รางวัลบอส/PVP ทางเมลจริง

## นอกขอบเขต (ไว้ระบบถัดไป)
- แจ้งเตือนเมลใหม่แบบทันทีข้ามเซิร์ฟ → ระบบที่ 2 (MessagingService)

- ระบบที่ 4 ความสำเร็จ/ฉายา: ผู้ใช้กำหนดว่า **อยู่ในเมนูเดียวกับสมุดสะสม** · ชื่อเรืองแสงเหนือหัว · VIP ได้ฉายาด้วย
