# ระบบโซเชียล — หินเวทสื่อสาร (Speaking Stone)

สเปกออกแบบ 2026-09-08 · sub-project: เฟส 3 ของแผนไอเทม/กระเป๋า

## ภาพรวม

หินเวทสื่อสารคือ "โทรศัพท์" ของโลกยุคกลาง+เวทมนตร์ กด **P** บนคอม หรือปุ่มกลมเล็กมุมขวาล่าง
บนมือถือ (ขนาดเท่าปุ่มกระเป๋า) แล้วหน้าจอหินจะเปิดขึ้นกลางจอ

ดีไซน์: **หินเวทที่ทำตัวเหมือนสมาร์ทโฟน** — ตัวเรือนหินสลักรูน ขอบเรืองแสง แต่ข้างในเป็นกริดไอคอน
แบบหน้าจอโทรศัพท์ 8 ปุ่ม กดแล้วสไลด์เข้าหน้าย่อย มีปุ่มย้อนกลับมุมซ้ายบน

เหตุผลที่เลือกทรงนี้: ผู้ใช้ขอ "โมเดิร์น + คล้ายจอมือถือ" และการวางเป็นกริดไอคอนทำให้เพิ่มปุ่มที่ 9, 10
ทีหลังได้โดยไม่ต้องรื้อ layout

## ขอบเขต: อะไรทำจริง อะไรทำแค่ปุ่ม

ผู้ใช้ระบุชัดว่าบางปุ่มยังไม่ต้องใช้งานได้ ตารางนี้คือสัญญาว่าอะไรเสร็จในเฟสนี้

| ปุ่ม | สถานะ | เหตุผล |
|---|---|---|
| บอร์ดกิลด์ + ฟีดลอยบนจอ | **ใช้งานได้** | หัวใจของระบบ |
| รายชื่อสหาย + นกพิราบ (แชท) | **ใช้งานได้** | หัวใจของระบบ |
| โปรไฟล์ (ดูอย่างเดียว) | **ใช้งานได้** | แรงค์/ชื่อ/รูปจาก Roblox |
| ธนาคาร + โอนเงิน | **ใช้งานได้** | ผู้ใช้ขอเงื่อนไขละเอียด |
| โทรจิต (เสียง) | ทำ UI + ปุ่มกดคุย | เสียงจริงเฟสหลัง (ดูหัวข้อ "โทรจิต") |
| ราคากลางของขาย | **ปุ่มอย่างเดียว** | ผู้ใช้สั่ง "ทำปุ่มมาก่อน" |
| เรียกทหารยาม / นักบวช / ช่างสร้าง | **ปุ่มอย่างเดียว** | รอความสามารถอาชีพ เฟส 4 |

ปุ่มที่ยังไม่ทำงานจะกดได้แต่ขึ้นข้อความ "ยังไม่เปิดใช้งาน" — ไม่ใช่ปุ่มตายที่กดแล้วเงียบ
เพราะผู้เล่นจะคิดว่าเกมค้าง

### 1. บอร์ดกิลด์

ทุกคนพิมพ์แล้วกดส่ง ข้อความโผล่เป็นกล่องเรียงจากใหม่ไปเก่า แต่ละกล่องมี:
รูปหน้าตัวละครจาก Roblox · ชื่อผู้เล่น · ข้อความ · เวลาที่โพสต์

**ขอบเขต: เฉพาะเซิร์ฟเวอร์นั้น** — อยู่ช่อง 1 เห็นเฉพาะของช่อง 1 ตามที่ผู้ใช้ระบุ
เก็บใน memory ของเซิร์ฟเวอร์ ไม่เข้า DataStore เซิร์ฟเวอร์ปิดคือหาย (ผู้ใช้เลือก)

- เก็บสูงสุด **50 โพสต์** เกินนั้นตัดอันเก่าสุดทิ้ง
- ข้อความยาวสุด **200 ตัวอักษร**
- กันสแปม: โพสต์ได้ทุก **5 วินาที** ต่อคน

**ฟีดลอยบนจอเกม** (ผู้ใช้ยืนยัน 2026-09-08): โพสต์ใหม่โผล่ชิดซ้ายของจอเกมโดยไม่ต้องเปิดหิน
แสดง **5 โพสต์ล่าสุด** อยู่ **10 วินาที** แล้วค่อยๆ จางหาย

- โพสต์ที่ 6 ดันอันเก่าสุดออก (ไม่รอให้ครบ 10 วิ)
- ฟีดต้องไม่บังการเล่น: ไม่รับคลิก (Active = false) และหลบแถบสถานะซ้ายล่างของ HUD
- ในหน้าบอร์ดของหิน ยังเห็นครบ 50 โพสต์เหมือนเดิม ฟีดเป็นแค่ตัวแจ้งเตือน

### 2. รายชื่อสหาย

สองแท็บ: **รายชื่อ** กับ **แชท**

- **เพิ่มเพื่อน**: พิมพ์ชื่อผู้เล่นที่อยู่ในเซิร์ฟเวอร์เดียวกัน → ส่งคำขอ → อีกฝ่ายกดรับ
  (ไม่ใช่เพิ่มฝ่ายเดียว เพราะจะกลายเป็นสแปม)
- **เก็บถาวร** ใน profile ของทั้งสองฝั่ง เจอกันคนละเซิร์ฟเวอร์ก็ยังเป็นเพื่อน
- แสดงสถานะ **ออนไลน์ในเซิร์ฟเวอร์นี้** (จุดเขียว) หรือไม่อยู่ (จุดเทา)
- สูงสุด **50 คน**

**นกพิราบ = แชทข้อความ** เลือกเพื่อนแล้วพิมพ์คุยกัน

- คุยได้เฉพาะตอน **ทั้งคู่อยู่ในเซิร์ฟเวอร์เดียวกัน** — ผู้ใช้ยืนยันแล้วว่ารับได้
  (ข้ามเซิร์ฟเวอร์ต้องใช้ MessagingService ซึ่งมีโควตาจำกัด ไม่คุ้มในเฟสนี้)
- เก็บ **30 ข้อความล่าสุด** ต่อคู่สนทนา อยู่ใน memory หายเมื่อเซิร์ฟเวอร์ปิด
- มีจุดแดงเตือนเมื่อมีข้อความใหม่ ทั้งบนไอคอนหินและในรายชื่อ

### 3. โทรจิต (เสียง)

**เฟสนี้ทำ UI + ปุ่ม "เริ่มโทรจิต" แต่ยังไม่มีเสียงจริง**

เหตุผล — Roblox VoiceChat มีข้อจำกัดที่แก้จากโค้ดไม่ได้:
1. ต้องเปิดใน Creator Dashboard และผ่าน age verification
2. ผู้เล่นแต่ละคนต้องยืนยันอายุเอง
3. **เลือกคุยเฉพาะคนไม่ได้** — API ให้ปิด/เปิดเสียงรายคนเท่านั้น ไม่มี "ห้องสนทนาส่วนตัว"

ทางที่ทำได้จริงคือ: ใช้ระยะห่าง (คนใกล้ได้ยิน) หรือ mute ทุกคนยกเว้นคู่สนทนา
ซึ่งได้ผลใกล้เคียง "โทรจิต" แต่ต้องเปิด VoiceChat ทั้งเกมก่อน

**แผนที่ผู้ใช้ยืนยันแล้ว**: ทำทีหลังตอนทุกอย่างพร้อม โดยจะเปิด VoiceChat ทั้งเกมแบบ
ให้ผู้เล่นเปิดระบบเสียงและยืนยันอายุเอง (ค่าเริ่มต้นปิด) แล้วจึงใช้การ mute ทุกคนยกเว้นคู่สนทนา
เพื่อจำลอง "โทรจิต"

กดปุ่มตอนนี้จะขึ้น "โทรจิตยังไม่เปิดใช้งาน" พร้อมอธิบายสั้นๆ

### 4. โปรไฟล์

แสดง: รูปหน้าจาก Roblox · ชื่อ · **แรงค์ตามเลเวล** · เลเวล · วันเกิด · เพศ

**แรงค์ 7 ขั้น** (ผู้ใช้เลือก) — คำนวณจากเลเวลล้วน ไม่เก็บในข้อมูล:

| แรงค์ | เลเวล | สี |
|---|---|---|
| F | 1-9 | เทา |
| E | 10-24 | เขียวอ่อน |
| D | 25-39 | เขียว |
| C | 40-54 | ฟ้า |
| B | 55-69 | ม่วง |
| A | 70-89 | ส้ม |
| S | 90-100 | ทอง (เรืองแสง) |

**วันเกิด/เพศ/รูปส่วนตัว: แสดงอย่างเดียว ยังแก้ไม่ได้** ตามที่ผู้ใช้สั่ง
แต่ profile schema จะมีช่องรอไว้แล้ว (`Birthday`, `Gender`, `AvatarImage`) จะได้ไม่ต้องย้ายข้อมูลทีหลัง
ค่าเริ่มต้นแสดง "ยังไม่ระบุ"

### 5. ธนาคาร

**แยกกระเป๋ากับธนาคาร** (ผู้ใช้เลือก) — เงินในกระเป๋าหายตอนตาย เงินในธนาคารปลอดภัย

- **ฝาก / ถอน**: ย้ายระหว่างกระเป๋ากับธนาคารของตัวเอง
- **โอน**: ใส่ชื่อ **@ชื่อผู้เล่น** ให้ถูก + จำนวนเงิน
  - **คนรับต้องอยู่ในเซิร์ฟเวอร์นั้นตอนนั้น** (ผู้ใช้ระบุ)
  - โอนจากธนาคารเข้าธนาคาร
  - พิมพ์ชื่อผิด = ปฏิเสธ ไม่หักเงิน
  - เงินไม่พอ = ปฏิเสธ
- ยอดเงินเก็บใน profile ถาวร

**กฎเหล็ก:** ทุกการเคลื่อนไหวของเงินตัดสินฝั่งเซิร์ฟเวอร์ — client ส่งได้แค่ "อยากโอนเท่านี้ให้คนนี้"
เซิร์ฟเวอร์เช็คยอด เช็คชื่อ แล้วหัก-เพิ่มในธุรกรรมเดียว ไม่มีทางที่เงินจะหายระหว่างทางหรือเพิ่มขึ้นเอง

### 6-8. ปุ่มที่ยังไม่ทำงาน

**ราคากลางของขาย** · **เรียกทหารยาม** · **เรียกนักบวช** · **เรียกช่างสร้าง**

กดแล้วขึ้นข้อความบอกว่ายังไม่เปิด ปุ่มเรียกอาชีพจะทำงานได้เมื่อเฟส 4 (ความสามารถอาชีพ) เสร็จ
ตอนนั้นจะส่งสัญญาณไปหาคนที่มี Role นั้นในเซิร์ฟเวอร์พร้อมพิกัดคนเรียก

## โครงสร้างโค้ด

ตามแบบเดิมของโปรเจ็ค: server เป็นเจ้าของข้อมูลทั้งหมด client แค่ขอและวาด

```
src/ReplicatedStorage/
  SocialConfig.lua          ตัวเลขทั้งหมด (ขีดจำกัด แรงค์ คูลดาวน์)
  UI/SocialGui.lua          หน้าจอหินเวท 8 หน้า

src/ServerScriptService/
  GuildBoard.lua            โพสต์ 50 อันล่าสุด (memory)
  Friends.lua               รายชื่อเพื่อน (profile) + แชท (memory)
  Bank.lua                  ยอดเงิน + โอน (profile)
  PlayerSocial.server.lua   ต่อเข้า lifecycle + รับ remote

src/StarterPlayerScripts/
  SocialController.client.lua   ปุ่ม P / ปุ่มมือถือ / วาดหน้าจอ
```

**เหตุผลที่แยกเป็น 3 โมดูล** ไม่ใช่ก้อนเดียว: บอร์ด/เพื่อน/ธนาคาร ไม่เกี่ยวกันเลย
แต่ละอันทดสอบแยกได้ และเฟสหลังจะแตะแค่อันเดียวโดยไม่กระทบอันอื่น

### Remote ที่เพิ่ม

| ชื่อ | ทิศทาง | ใช้ทำอะไร |
|---|---|---|
| `RequestSocialData` | client → server | ขอข้อมูลตอนเปิดหน้าจอ |
| `SocialUpdate` | server → client | ส่งบอร์ด/เพื่อน/ยอดเงิน |
| `RequestGuildPost` | client → server | โพสต์บอร์ด |
| `RequestFriendAction` | client → server | เพิ่ม/รับ/ลบเพื่อน |
| `RequestPigeonMessage` | client → server | ส่งข้อความ |
| `RequestBankAction` | client → server | ฝาก/ถอน/โอน |
| `SocialNotify` | server → client | มีข้อความใหม่ / คำขอเพื่อน |

ทุก remote ที่ client ส่งเข้ามาจะตรวจชนิดข้อมูล ความยาว และสิทธิ์ก่อนเสมอ
เพราะ client โกงได้ทุกอย่าง

### เพิ่มใน profile

```lua
Social = {
    Friends = {},        -- {userId = ชื่อ} เก็บถาวร
    Pending = {},        -- คำขอเพื่อนที่ยังไม่ตอบ
    Bank = 0,            -- เงินในธนาคาร
    Birthday = nil,      -- ยังแก้ไม่ได้ เตรียมช่องไว้
    Gender = nil,
    AvatarImage = nil,
}
```

## ปุ่มเปิด

- **คอม: P** ผ่าน `ContextActionService` + Sink เหมือนปุ่ม I ของกระเป๋า
  (บทเรียนจากคราวก่อน: ปุ่ม I ไปชนกับ zoom ของ Roblox ต้อง Sink ถึงจะกันได้)
- **มือถือ: ปุ่มกลมมุมขวาล่าง ขนาดเท่าปุ่มกระเป๋า** (ROLL_SIZE) วางในกลุ่มปุ่มเดิม
  ใช้สีดำโปร่งใสชุดเดียวกับปุ่มอื่น

## ความเสี่ยงที่รู้ล่วงหน้า

1. **รูปหน้าตัวละคร** — `GetUserThumbnailAsync` ช้าและมีโควตา โปรเจ็คมี `AvatarThumbnails.lua`
   ที่ทำ cache + จัดคิวไว้แล้ว จะใช้ตัวนั้น ไม่เขียนใหม่
2. **บอร์ดหายตอนเซิร์ฟเวอร์ปิด** — ผู้ใช้ยอมรับแล้ว แต่ต้องบอกผู้เล่นในหน้าจอ
   ไม่งั้นจะคิดว่าบั๊ก
3. **แชทข้ามเซิร์ฟเวอร์ไม่ได้** — ข้อจำกัดจริง ต้องเขียนบอกใน UI ให้ชัด
4. **ช่องพิมพ์บนมือถือ** — คีย์บอร์ดมือถือจะบังครึ่งจอ ต้องเลื่อนหน้าจอหินขึ้นตอนพิมพ์
5. **การทดสอบ** — เพื่อน/แชท/โอนเงิน ต้องมี 2 ผู้เล่น ทดสอบเต็มรูปแบบต้อง publish

## ลำดับการทำ

1. โครงหน้าจอ + ปุ่ม P/มือถือ + 8 ไอคอน (ปุ่มที่ยังไม่ทำแสดงข้อความ)
2. บอร์ดกิลด์ (ง่ายสุด ไม่ต้องเก็บถาวร ได้เห็นผลเร็ว)
3. โปรไฟล์ + แรงค์ (อ่านอย่างเดียว)
4. ธนาคาร (ระวังเรื่องเงินมากที่สุด)
5. เพื่อน + นกพิราบ
6. ทดสอบใน Play แล้ว publish ทดสอบ 2 บัญชี
