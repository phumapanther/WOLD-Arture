# คอมโบดาบ 4 จังหวะ + ทางเข้าท่าจาก Mesh2Motion — สเปก

ผู้ใช้อนุมัติแบบในแชท 2026-10-13 · งานที่ 1 จาก 4 ของ "อัปเกรดระบบอนิเมชัน/การต่อสู้แบบ MMORPG"
(งานถัดไป: 2 สกิล/เอฟเฟ็กต์อลังการ · 3 ริก/สร้างมอนใหม่ · 4 ต้นไม้/หินใหม่จาก Hunyuan3D)

## เป้าหมาย
ฟันดาบให้รู้สึกเหมือน MMORPG: คลิกต่อเนื่องเป็นคอมโบ ท่าลื่นไม่หน่วง ตีโดนแล้วมีน้ำหนัก และให้ผู้ใช้ทำท่าใหม่ใน
Mesh2Motion ทีละท่า (ท่าละ 1-3 วัน) แล้วเอาเข้าเกมได้ด้วยคำสั่งเดียว โดยเกมไม่พังระหว่างที่ท่ายังไม่ครบ

## การตัดสินใจของผู้ใช้ (ห้ามเปลี่ยนโดยไม่ถาม)
| เรื่อง | ที่เลือก |
|---|---|
| ตัวผู้เล่น | **คงอวตาร R15 ของผู้เล่น** — ท่าต้องแปลงเป็นข้อต่อ R15 |
| ทางเข้าของท่า | **เครื่องมือแปลงอัตโนมัติ** GLB → R15 (ไม่ใช้ Blender) |
| คอมโบ | **4 จังหวะ** หิต 1-3 = คลิก · **หิต 4 = กดค้างชาร์จแล้วปล่อย** |
| ชาร์จได้เมื่อไหร่ | **ทุกจังหวะ** รวมตอนเริ่ม (กดค้างจากท่ายืนก็ได้) แล้วคอมโบกลับหิต 1 |
| ขั้นชาร์จ | **สองขั้น** ค้าง 0.6 วิ = ขั้น 1 · 1.5 วิ = เต็ม · ปล่อยก่อน 0.6 วิ = คลิกธรรมดา |
| เดินตอนชาร์จ | **ความเร็ว 6** (ปกติ 8) ไม่วิ่ง ไม่กระโดด |
| ความรู้สึก | ก้าวพุ่ง + หันหาเป้า · หยุดชะงักตอนโดน + กล้องสั่น · แสงรอยดาบ + ประกาย · กลิ้งยกเลิกท่าได้ · **เลขดาเมจลอย** |
| โครงระบบ | **เครื่องผู้เล่นเล่นท่าทันที + เซิร์ฟตัดสินดาเมจ** (ไม่ใช่ไคลเอนต์ตัดสินการโดน) |

## ข้อเท็จจริงที่ออกแบบตาม
- **Mesh2Motion** (MIT · ท่าในคลัง CC0 ใช้เชิงพาณิชย์ได้) นำเข้า/ส่งออก **GLB/glTF เท่านั้น** · ทำงานแบบ
  *เลือกท่าจากคลังของมัน* แล้วปรับโครงให้พอดีโมเดล — เท่าที่เอกสารบอก ไม่ได้ให้คีย์ท่าเอง
  → ตัวแปลงรับ **GLB ที่มีโครงคนจากที่ไหนก็ได้** (Mesh2Motion หรือ Blender export glTF ถ้าคลังไม่มีท่าที่อยาก)
- **Roblox ไม่มี root motion** — การเลื่อนตัวในท่าต้องดันด้วยโค้ด
- ตอนนี้ดาบมีท่าเดียว (`Sword_Slash` จาก `animgen/sword.lua`) · ระบบลำดับท่า `attacks` + `chainIndex` มีอยู่แล้วใน `PlayerCombat`
- ตอนนี้ **คลิกแรกยกการ์ดอย่างเดียว ไม่ฟัน** และเครื่องผู้เล่น **รอเซิร์ฟตอบก่อนเล่นท่าตัวเอง** (`CombatController` บรรทัด ~234)
  = ช้ากว่าคลิกเท่าปิง — สองข้อนี้คือสิ่งที่งานนี้เปลี่ยนสำหรับดาบ
- มอนมีเลขดาเมจลอยอยู่แล้ว (`Mobs.server` `showDamageNumber` สร้างฝั่งเซิร์ฟ ทุกคนเห็น) · ผู้เล่น/บอทสนามยังไม่มี

## ส่วนที่ 1 — ตัวแปลง `tools/glb-to-r15.js`
**ใช้:** `node tools/glb-to-r15.js <ไฟล์.glb> [--name Sword_Combo1] [--loop] [--clip <ชื่อคลิปใน glb>]`
ไฟล์หนึ่งอาจมีหลายคลิป (Mesh2Motion ส่งออกหลายท่าในไฟล์เดียวได้) → ไม่ระบุ `--clip` = แปลงทุกคลิป ชื่อท่า = ชื่อคลิป

**ขั้นตอน**
1. อ่าน GLB (หัว 12 ไบต์ + ก้อน JSON + ก้อน BIN) ด้วย Node ล้วน ไม่มี dependency · อ่าน nodes / skins / animations
   (channel rotation/translation · interpolation LINEAR/STEP/CUBICSPLINE)
2. **แมพกระดูก → ข้อต่อ R15 15 ชิ้น** ผ่านตาราง `tools/glb-to-r15.bones.json` (แก้ได้) มีชุดชื่อที่พบบ่อยในตัว
   (Mixamo `mixamorig:*` · ชื่อทั่วไป Hips/Spine/Chest/Neck/Head/UpperArm/LowerArm/Hand/UpLeg/Leg/Foot) และ
   **ชุดของ Mesh2Motion เติมหลังได้ไฟล์แรกจากผู้ใช้** · กระดูกที่ R15 ไม่มี (นิ้ว · สันหลังหลายท่อน · ไหปลาร้า)
   รวมการหมุนเข้าข้อต่อ R15 ที่ใกล้สุดตามสายพ่อแม่ · หาไม่เจอสักชิ้นในข้อหลัก (สะโพก แขน ขา) = หยุดพร้อมรายชื่อกระดูก
   ที่เจอ (ไม่เดาเงียบๆ)
3. **ย้ายการหมุนแบบ "ส่วนต่างจากท่ายืน"**: ต่อกระดูกต้นทางคำนวณการหมุนในโลกตอนท่ายืน (rest/bind) กับที่เวลา t →
   ส่วนต่างในโลก → แปลงเป็น `Pose.CFrame` ของข้อต่อ R15 เทียบกับข้อต่อพ่อ ในกรอบของ C0 ของ Motor6D นั้น
   ท่าจึงใช้ได้กับอวตารทุกสัดส่วน · แปลงแกน glTF (หน้า = +Z) → Roblox (หน้า = −Z) ด้วยการหมุน 180° รอบ Y
4. **สะโพก**: การยก/ย่อแนวดิ่งเก็บเป็นตำแหน่งของ pose `LowerTorso` · **การเลื่อนแนวราบตลอดท่าถูกดึงออก** เป็นตัวเลข
   `lunge` (สตัด ตามแนวหน้า) ให้โค้ดดันตัวแทน · การเลื่อนข้าง/ถอยหลังทิ้ง
5. สุ่มตัวอย่างที่ 30 fps แล้วตัดคีย์ที่ไม่จำเป็น (คลาดจากเส้นตรงไม่เกิน 0.5°) · ท่า `--loop` ตั้ง Looped
6. **จังหวะดาบโดน**: อ่าน `assets/anims/sword/markers.json` `{ "Sword_Combo1": { "hitStart": 0.24, "hitEnd": 0.36 } }`
   ไม่มี = **ประมาณจากความเร็วของมือขวา** (ช่วงที่เร็วกว่า 60% ของจุดสูงสุด) แล้วพิมพ์ค่าที่เดาให้เห็น · ท่า loop ไม่ต้องมี
7. เขียน **`animgen/generated/<ชื่อ>.lua`** (โครงเดียวกับ `animgen/*.lua` เดิม: ลบเฉพาะท่าของตัวเอง แล้วสร้าง
   KeyframeSequence + KeyframeMarker `HitStart`/`HitEnd` ใน `ServerStorage.WOLD_Animations`) และอัปเดตแถวใน
   **`src/ReplicatedStorage/AnimTimings.lua`** (ข้อมูลล้วน `{ length, hitStart, hitEnd, lunge }` ต่อชื่อท่า)
8. พิมพ์คำสั่งถัดไป: `node tools/run-luau.js animgen/generated/<ชื่อ>.lua --no-lib` · `node tools/preview-anim.js …`
   แล้วผู้ใช้ Save to Roblox → ใส่ id ใน `CombatConfig`

**โมเดลที่ใช้ใน Mesh2Motion:** โมเดลคนตัวอย่างของ Mesh2Motion เอง (หรือโมเดลคนอะไรก็ได้) — ย้ายแบบส่วนต่างการหมุน
ไม่ขึ้นกับรูปร่างโมเดล

## ส่วนที่ 2 — ระบบคอมโบ
**ข้อมูล** `CombatConfig.Weapons.Sword.combo` (อาวุธที่มี `combo` ใช้ระบบใหม่ · อาวุธอื่นใช้ `attacks` แบบเดิมไม่เปลี่ยน):
```lua
combo = {
  light = {   -- หิต 1-3 วนตามลำดับ
    { anim = "Sword_Combo1", id = "", damage = 16 },
    { anim = "Sword_Combo2", id = "", damage = 16 },
    { anim = "Sword_Combo3", id = "", damage = 22 },
  },
  chargeAnim = { anim = "Sword_Charge", id = "" },            -- ท่าง้างค้าง (loop)
  finisher = {                                               -- หิต 4 ตอนปล่อย
    anim = "Sword_ChargeRelease", id = "",
    stages = {
      { holdSeconds = 0.6, damage = 32, effect = "stagger",   knockback = 6 },
      { holdSeconds = 1.5, damage = 48, effect = "knockdown", knockback = 14 },
    },
  },
  tapSeconds = 0.25,        -- ปล่อยก่อนนี้ = คลิก · ค้างถึงนี้ = เข้าท่าง้าง
  chainResetSeconds = 0.8,  -- ไม่กดต่อหลังท่าจบเกินนี้ = กลับหิต 1
  chargeWalkSpeed = 6,
  lungeMax = 6,
  fallback = "Sword_Slash", -- ท่าที่ยังไม่มี id = เล่นท่าเดิมนี้ + ใช้จังหวะของท่าเดิม
}
```
จังหวะ (`windup = hitStart` · `active = hitEnd − hitStart` · `recovery = length − hitEnd`) และระยะพุ่ง **อ่านจาก
`AnimTimings` ตามชื่อท่า** — ไม่มีแถวหรือ id ยังว่าง = ใช้ของ `fallback`

**กติกาคอมโบ = โมดูลข้อมูลล้วน `ReplicatedStorage/ComboRules.lua`** ใช้ร่วมเครื่องผู้เล่น (ทำนาย) และเซิร์ฟ (ตรวจ)
- สถานะ: `idle` · `swing(step)` · `charging(since)` · ตัวนับ `step` (1-3) · `lastSwingEndAt` · `buffered`
- **กด**: ว่าง → จดเวลากด (ยังไม่ฟัน) · กำลังฟัน → จด `buffered = true`
- **ค้างครบ `tapSeconds`** (ยังไม่ปล่อย) → เข้า `charging` (ถ้ากำลังฟันอยู่ = เข้าทันทีที่ท่าปัจจุบันตัดได้)
- **ปล่อย**: ยังไม่ถึง `tapSeconds` หรือ charging แต่ไม่ถึงขั้น 1 → **หิตเบาลำดับถัดไป** · charging ถึงขั้น 1/เต็ม →
  **หิต 4 ขั้นนั้น** แล้ว `step` กลับเป็น 0
- **ตัดท่าได้** (ต่อหิตถัดไปหรือกลิ้ง) ตั้งแต่ `hitEnd` ของท่าปัจจุบัน — หิตที่บัฟเฟอร์ไว้ออกตรงนั้น
- ว่างนานเกิน `chainResetSeconds` หลังท่าจบ → `step = 0`
- **คลิกแรกฟันเลย** สำหรับอาวุธที่มี `combo` (เลิกกติกา "คลิกแรกยกการ์ด" เฉพาะดาบ) · ท่ายืนถือดาบขึ้นเองหลังฟันเหมือนเดิม

**เซิร์ฟ (`PlayerCombat`)** — remote ใหม่ `ComboInput(action, aim)` action = `press` / `release` / `chargeBegin`
- เดินกติกาเดียวกันด้วยนาฬิกาของเซิร์ฟ: **นับลำดับหิตเอง** (ไคลเอนต์บอกแค่ "กด/ปล่อย") · **จับเวลาชาร์จเอง**
  จาก `chargeBegin` ที่เซิร์ฟได้รับ (เผื่อปิงได้ไม่เกิน 0.15 วิ) — ไคลเอนต์อ้าง "ชาร์จเต็ม" ทั้งที่ไม่ได้ค้างไม่ได้
- ด่านเดิมทั้งหมดยังอยู่ก่อนเริ่มท่า (`Deny.Blocked` · สนามยังไม่เริ่ม · อาวุธพัง · ยกการ์ดปัด · กับดัก)
- ผ่าน = ตั้ง `pendingAttack` ด้วยดาเมจ/ผลของหิตนั้น ให้ลูป Heartbeat + `resolveHit` เดิมทำงาน (ตีบวก · ตี้ · ทีมสนาม ·
  ปัดป้อง ใช้กติกาเดิมทั้งหมด) · หิต 4 ใช้ `StatusEffects.Stagger` / `Knockdown` + แรงถอย (มอน/บอทผ่าน MobAccess)
- ระหว่างชาร์จตั้งแอตทริบิวต์ `WOLD_Charging` บนตัว Player → `PlayerMovement` หนีบความเร็ว 6 ไม่วิ่ง ·
  กระโดดไม่ได้ผ่านทางเดียวกับที่ `StatusEffects` คุมการกระโดดอยู่แล้ว
- ไม่ผ่าน → `ComboRejected(reason)` ถึงคนกด (ใช้ข้อความเดียวกับ `Deny`)
- กระจาย `CombatStateChanged(player, "combo", step | "charge" | "finisher", stage)` **ถึงทุกคนยกเว้นคนกด**
- **กลิ้งระหว่างคอมโบ**: `PlayerActions` ถาม `CombatAccess.CanRoll(player)` — ช่วงง้าง/ดาบกำลังโดน = ไม่ได้ ·
  ตั้งแต่ `hitEnd` = ได้ และล้างท่าที่เหลือ (busy/pending)

**เครื่องผู้เล่น (`ComboController.client.lua` ใหม่)**
- อ่านคลิกซ้ายแบบกด/ปล่อย · มือถือ: ปุ่มโจมตีใน `TouchActionGui` ส่งทั้งกดและปล่อยผ่าน BindableEvent ใน
  `ReplicatedStorage` (กฎ: ช่องทางฝั่งไคลเอนต์ห้ามอยู่ใน PlayerGui)
- เดินกติกาเดียวกันเพื่อ **เล่นท่าทันที** · `CombatController` เดิมข้ามอาวุธที่มี `combo` (ไม่ยิง `RequestAttack` ซ้ำ)
- **พุ่ง**: ดันตัวไปข้างหน้า `lunge` (หนีบ 0-`lungeMax`) ช่วงง้าง ด้วยแรงชั่วคราวฝั่งเครื่องผู้เล่น · เจอกำแพง (เรย์) = หยุด
- **หันหาเป้า**: ตอนเริ่มท่า หาศัตรู (มอน/บอท/ผู้เล่นที่ตีได้) ใกล้สุดใน 10 สตัด กรวยหน้า 70° → หันไปหา (ไคลเอนต์หันเอง ·
  เซิร์ฟห้ามตั้ง CFrame ผู้เล่น)
- ได้ `ComboRejected` → หยุดท่า/แสงที่ทำนายไว้ทันที + ข้อความ

## ส่วนที่ 3 — ความรู้สึกและเอฟเฟ็กต์ (`UI/CombatFx.lua` ฝั่งไคลเอนต์)
- **หยุดชะงัก + กล้องสั่น (เฉพาะจอคนตี)**: ที่ `hitStart` เครื่องผู้เล่นตรวจทับซ้อนเอง (เพื่อความรู้สึกเท่านั้น ดาเมจจริงตามเซิร์ฟ)
  โดน = หยุดท่าตัวเอง (`AdjustSpeed(0)`) เบา 0.06 · ขั้น 1 0.12 · เต็ม 0.18 วิ แล้วเล่นต่อ + สั่นกล้องเบา/แรงตามหิต ·
  คุณภาพต่ำสั่นน้อยลง · ไม่แตะฟิสิกส์และนาฬิกาเซิร์ฟ
- **แสงรอยดาบ (ทุกคนเห็น)**: Trail ระหว่าง Attachment โคน/ปลายใบ (หาจากกล่องของโมเดลดาบในมือ · สกินที่ปั้นมาใส่
  Attachment ชื่อ `TrailBase`/`TrailTip` เองได้) เปิดเฉพาะ `hitStart − 0.05` ถึง `hitEnd + 0.05` · สีตามสกิน (ตาราง
  สีในคอนฟิก · ไม่มี = ขาวฟ้า)
- **ชาร์จเรืองแสง**: ขั้น 1 ขาว · เต็ม ทอง + ประกาย (PointLight + ParticleEmitter บนใบดาบ) ทุกคนเห็น
- **ประกายตอนโดน (ทุกคนเห็น)**: เกิดที่จุดโดน ไปพร้อมเสียงโดนเดิม · คุณภาพต่ำลดอนุภาคครึ่งหนึ่ง
- **เลขดาเมจลอย**: ย้าย `showDamageNumber` ของ `Mobs.server` ไปเป็นโมดูล `DamageNumbers.lua` (เซิร์ฟสร้างหมุด + แอตทริบิวต์

## ความเสี่ยงที่รู้
- **ชื่อกระดูกของ Mesh2Motion ยังไม่รู้จนได้ไฟล์แรก** — ตารางในตัวแปลงเติมตอนนั้น (ใช้เวลาไม่นาน)
- การย้ายท่าข้ามโครงอาจเพี้ยนบางข้อต่อ (ข้อมือ/ไหล่) → ตัวแปลงรับค่าชดเชยต่อข้อต่อใน `glb-to-r15.bones.json`
- ทำนายท่าที่เครื่องผู้เล่น: ถ้าเซิร์ฟปฏิเสธบ่อย (เช่นปิงสูงมาก) ท่าจะถูกตัดกลางคัน — ยอมรับได้ เพราะเกิดเฉพาะตอนถูกห้ามจริง
- ประกาย/ชะงักที่เครื่องผู้เล่นเห็นอาจไม่ตรงกับดาเมจจริงในบางครั้ง (เซิร์ฟว่าพลาด) → ไม่มีเลขดาเมจขึ้น คือสัญญาณที่ถูกต้อง
