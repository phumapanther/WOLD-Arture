# tiktok-bridge — TikTok LIVE → WOLD Arture

ไลก์เสกมอน ของขวัญหล่นหีบ กดซับได้บอสที่มีชื่อคนกดอยู่บนหัว คนดูพิมพ์คำสั่งบังคับตัวแอดมิน
และท็อป 3 ของไลฟ์สั่งฟ้าฝนกับเวลาได้

```
เบราว์เซอร์ TikTok LIVE
      ↓  tiktok-live-connector
tools/tiktok-bridge/bridge.js      ← โปรแกรมนี้ ถือคิวอีเวนต์ไว้
      ↓  HTTP GET /events?after=<id>   (เกมเป็นฝ่ายถาม ทุก 0.5 วิ)
src/ServerScriptService/TikTokLive.server.lua
      ↓  เรียกระบบที่มีอยู่แล้วในเกม
MobAccess · ChestAccess · StatusEffects · Vitals · WeatherAccess · DayNightAccess
```

## ทำไมเกมต้องเป็นฝ่ายถาม ไม่ใช่เราส่งเข้าไป

**เซิร์ฟเวอร์ Roblox รับ HTTP ขาเข้าไม่ได้** ไม่มี listener ไม่มีพอร์ต `HttpService` โทรออกได้ทางเดียว
ดีไซน์แบบ "POST เข้า Roblox" จึงสร้างไม่ได้เลย (โค้ดที่ยิงไปที่ `127.0.0.1:8080/tiktok-event` แล้วดูเหมือนทำงาน
คือกำลังคุยกับอย่างอื่นอยู่)

ตัวนี้จึงเก็บอีเวนต์ใส่คิวที่มี **เลขไอดีเรียงกัน** แล้วเกมถามว่า "มีอะไรหลังไอดีที่ฉันเห็นล่าสุดบ้าง"
ข้อดีที่ได้มาฟรีคือ **หลุดแล้วไม่หาย** — poll ตก เซิร์ฟแลค Studio รีสตาร์ท ก็แค่ถามด้วยไอดีเดิมอีกครั้ง

## เริ่มใช้

```bash
cd tools/tiktok-bridge
npm install                      # ครั้งแรกครั้งเดียว
node bridge.js --user PHUMAPANTHER
```
หรือดับเบิลคลิก `run.bat` (ติดตั้ง dependency ให้เองถ้ายังไม่มี)

ในเกม: `src/ReplicatedStorage/TikTokConfig.lua` → `Url` ต้องชี้มาที่นี่ (ดีฟอลต์ `http://127.0.0.1:8787`)
และต้องเปิด **Game Settings → Security → Allow HTTP Requests**

## เช็ค 4 ข้อก่อนกดไลฟ์

**TikTok Live Studio ไม่เกี่ยวกับตัวนี้เลย** สะพานไม่ได้อ่านจาก Live Studio และไม่ต้องมี OBS — มันคุยกับ API
สาธารณะของ TikTok ด้วย *ชื่อช่อง* เงื่อนไขเดียวคือ **บัญชีต้องอยู่ในสถานะ LIVE จริง** (ไลฟ์จากมือถือ
Live Studio หรือ OBS ก็ได้ ไม่ต่างกัน) เปิด Live Studio ค้างไว้แต่ยังไม่กด "ไปไลฟ์" = ยังต่อไม่ได้

| # | ต้องมี | ถ้าไม่มีจะเห็นอะไร |
|---|---|---|
| 1 | บัญชีกด **ไปไลฟ์** แล้วจริง และชื่อช่องใน `run.bat` ถูก | `❌ ต่อไลฟ์ไม่ได้: Failed to retrieve Room ID` วนทุก 15 วิ |
| 2 | **สะพานเปิดอยู่** (หน้าต่าง `run.bat` ค้างไว้ทั้งไลฟ์) | ในเกมเงียบ · `[TikTok] ต่อสะพานไม่ได้` ใน Output |
| 3 | **เกมรันอยู่** — Studio กด F5 หรือเข้าเกมที่ publish | `curl /health` ขึ้น `polls: 0` กับ `gameCursor: -1` |
| 4 | **มีแอดมินยืนอยู่ในเซิร์ฟ** (บัญชีใน `AdminRoster`) | เกมไม่ถามสะพานเลย (ตั้งใจ — ไม่มีแอดมินก็ไม่มีที่ให้ของโผล่) |

**เกมที่ publish แล้วยังใช้ไม่ได้ทันที** เซิร์ฟเวอร์ Roblox บนคลาวด์วิ่งมาที่ `127.0.0.1` ของเครื่องที่บ้านไม่ได้
ตอนนี้ที่ใช้ได้เลยคือ **ทดสอบใน Studio (F5)** · จะไลฟ์จากเกมจริงต้องต่อท่อก่อน ดูหัวข้อ
"เอาขึ้นเกมที่ publish จริง" ข้างล่าง

ดูว่าทั้งสายต่อกันติดจริงไหม: `curl http://127.0.0.1:8787/health` → ต้องได้ `connected: true` (ต่อไลฟ์ได้)
และ `polls` เพิ่มขึ้นเรื่อยๆ กับ `lastPollSecondsAgo` ต่ำๆ (เกมกำลังถามอยู่)

### ไฟล์ .bat ทั้งสี่ตัวต่างกันตรงไหน

ทั้งสี่ตัวรันโปรแกรมเดียวกัน ต่างแค่ธงที่ส่งให้ **ไลก์ / ของขวัญ / แชท / แผงปุ่ม ทำงานเหมือนกันหมดทุกตัว**

| ไฟล์ | ธง | ใช้เมื่อ |
|---|---|---|
| `run.bat` | — | ไลฟ์ที่เล่นใน **Studio** (เกมดึงเอง ไม่ผ่าน Open Cloud) |
| `run-live.bat` | `--push` | **ไลฟ์จริงตามปกติ** — เกมที่ publish แล้ว |
| `run-live-test.bat` | `--push --follow-boss --dump` | เหมือน `run-live` + **กดติดตามก็ได้บอส** (ทดสอบฟรี) + พิมพ์ payload ดิบครั้งแรกของแต่ละชนิด |
| `run-mock.bat` | `--mock` | ไม่ต่อไลฟ์ ยิงอีเวนต์สุ่มให้เองทุก 4 วิ ดูว่าทั้งสายทำงาน |

**เปิดได้ทีละตัวเท่านั้น** ทั้งสี่ใช้พอร์ต 8787 ตัวที่สองจะเปิดไม่ได้และบอกว่าพอร์ตชน — ปิดหน้าต่างเดิมให้หมดก่อน

ตอนไลฟ์จริงควรใช้ **`run-live.bat`** ไม่ใช่ตัว test เพราะ `--follow-boss` จะทำให้**คนกดติดตามทุกคนได้บอส**
ซึ่งคนกดติดตามมาถี่กว่าคนกดซับมาก (เพดานบอส 3 ตัวกันไว้อยู่ แต่บอสจะเต็มตลอดจากคนติดตาม ไม่เหลือให้คนกดซับ)

## ธงอื่น

| ธง | ทำอะไร |
|---|---|
| `--user <ชื่อ>` | ช่อง TikTok ที่จะเกาะ (ไม่ต้องมี @) **ต้องเป็นตัวพิมพ์เล็ก** |
| `--port <n>` | พอร์ต (ดีฟอลต์ 8787) ต้องตรงกับ `TikTokConfig.Url` |
| `--key <คำ>` | ต้องส่ง `?key=` มาด้วยถึงจะตอบ ตั้งให้ตรงกับ `TikTokConfig.Key` |
| `--follow-boss` | ให้ "กดติดตาม" ได้บอสด้วย ไม่ใช่แค่ "กดซับ" (ดีฟอลต์ปิด — ติดตามมาถี่กว่ามาก) |
| `--dump` | พิมพ์ payload ดิบของอีเวนต์แต่ละชนิดครั้งแรกออกมา |
| `--likes <n>` | กี่ไลก์ต่อมอนหนึ่งตัว (ดีฟอลต์ 1) |

## ติดตั้งบนเครื่องอื่น (เครื่องที่ใช้ไลฟ์จริง)

**เครื่องที่ไลฟ์ไม่ต้องมีเกม ไม่ต้องมี Studio ไม่ต้องมี Rojo** — โค้ดฝั่ง Roblox อยู่ในเกมที่ publish แล้ว
เครื่องนี้รันแค่สะพาน ต้องการแค่ **Node** กับ **โฟลเดอร์นี้**

```bash
git clone https://github.com/phumapanther/WOLD-Arture.git
cd WOLD-Arture/tools/tiktok-bridge
npm install
```
(หรือก๊อปแค่โฟลเดอร์ `tools/tiktok-bridge` ไปก็พอ ไม่ต้องเอาทั้งรีโป)

แล้วสร้างไฟล์ **`live.env`** เอง (ไฟล์นี้ไม่อยู่ใน git เพราะมีคีย์) ก๊อปจาก `live.env.example` แล้วใส่ 3 ค่า:

| ค่า | เอามาจากไหน |
|---|---|
| `ROBLOX_UNIVERSE_ID` | `10765335572` (ของเกมนี้ ไม่ต้องเปลี่ยน) |
| `ROBLOX_API_KEY` | create.roblox.com → Credentials → API Keys · **คีย์เดิมใช้ได้ทุกเครื่อง** ไม่ต้องสร้างใหม่ต่อเครื่อง |
| `TIKTOK_SIGN_KEY` | eulerstream.com → Dashboard · ใช้ได้ทุกเครื่องเหมือนกัน |

แก้ชื่อช่องใน `run-live.bat` บรรทัด `set TIKTOK_USER=` ถ้าไลฟ์จากบัญชีอื่น (**ตัวพิมพ์เล็ก**)

จากนั้นดับเบิลคลิก **`run-live.bat`** — เท่านี้จบ ไม่มีอะไรต้องตั้งใน Roblox อีก

**สองเครื่องเปิดพร้อมกันไม่ได้** ทั้งคู่จะส่งอีเวนต์ชุดเดียวกันเข้าเกม = ของโผล่สองเท่า ให้เปิดเครื่องเดียวต่อไลฟ์

## ทดสอบตอนไลฟ์จริงโดยไม่เสียเหรียญ

เปิดเบราว์เซอร์ไปที่ **http://127.0.0.1:8787/** จะได้**แผงปุ่ม** — กดปุ่มแล้วอีเวนต์จะวิ่งเข้าเกม
ด้วยเส้นทางเดียวกับของจริงทุกขั้น (คิว → เคอร์เซอร์ หรือ Open Cloud → handler ในเกม) ไม่ใช่การจำลอง

ใช้ได้ทั้งตอนยังไม่ไลฟ์และตอนไลฟ์จริง และ **ใช้ได้กับเกมที่ publish แล้วด้วย** (โหมด push ก็ยิงผ่าน Open Cloud
เหมือนกัน) — นี่คือวิธีเดียวที่จะรู้ว่าหีบทองกับบอสทำงานในเกมจริง โดยไม่ต้องซื้อของขวัญ 100 coins มาลอง

บนแผงมีบรรทัดสถานะบอกด้วยว่า **ไลฟ์ต่ออยู่ไหม** และ **เกมถามล่าสุดเมื่อไหร่** ถ้าขึ้น "ยังไม่เคย" คือเกมไม่ได้คุยกับสะพาน
(อยู่ใน Edit mode / ไม่มีแอดมินในเซิร์ฟ / โหมดไม่ตรง)

อยากเปิดแผงจากมือถือให้รัน `node bridge.js --host 0.0.0.0 ...` แล้วเข้าจาก IP ของเครื่องในวงแลน

### แล้วของจริงทดสอบยังไง

| อย่าง | ราคา | วิธี |
|---|---|---|
| **กดใจ** | ฟรี | บัญชีอื่น (มือถืออีกเครื่อง/ให้เพื่อนช่วย) แตะหัวใจรัวๆ ครบ 10 ครั้ง = มอน 1 ตัว · เจ้าของไลฟ์กดใจตัวเองไม่ได้ |
| **พิมพ์คำสั่ง** | ฟรี | พิมพ์ `!มึน` ในแชทไลฟ์จากบัญชีไหนก็ได้ |
| **กดซับ** | เสียเงิน | **ทดสอบฟรีได้ด้วยการกดติดตาม** — รันด้วย `--follow-boss` แล้ว "กดติดตาม" จากบัญชีอื่นจะได้บอสแบบเดียวกับกดซับ (ทางโค้ดเป็นเส้นทางเดียวกันทั้งหมด ต่างแค่ชื่ออีเวนต์) |
| **ของขวัญ** | ถูกสุด 1 coin | ส่ง **Rose** (1 coin) จากบัญชีอื่น = หีบเล็ก · ถ้าจะลองหีบกลาง/ทองโดยไม่เสีย 100 coins ให้แก้เกณฑ์ใน `giftTiers` บนหัว `bridge.js` ชั่วคราวให้ 1 coin เป็น `Chest_Gold` แล้วส่ง Rose ดอกเดียว |

**ลำดับที่แนะนำตอนไลฟ์จริงครั้งแรก:** เปิดแผงปุ่มกดให้ครบทุกอย่างก่อน (ฟรี เห็นผลทันที รู้ว่าฝั่งเกมพร้อม) →
ให้เพื่อนกดใจครบ 10 (ยืนยันว่าอีเวนต์จาก TikTok จริงเข้าถึง) → พิมพ์คำสั่งในแชท → กดติดตามด้วย `--follow-boss`
→ ค่อยลอง Rose 1 ดอกปิดท้าย · ถ้า 4 ข้อแรกผ่าน ของขวัญราคาแพงไม่มีเหตุให้พลาด เพราะเดินเส้นทางเดียวกับ Rose

## อีเวนต์ที่ส่งเข้าเกม

```jsonc
{ "kind": "mob",   "count": 2, "by": "somchai" }                          // ไลก์ครบ 10 × 2
{ "kind": "chest", "tier": "Chest_Gold", "label": "ใหญ่", "coins": 150 }   // ของขวัญ
{ "kind": "boss",  "by": "น้องเปิ้ล" }                                     // กดซับ
{ "kind": "cmd",   "text": "!มึน", "by": "มุก", "top": false }              // แชทที่ขึ้นต้นด้วย !
```

**ท็อป 3 คิดที่นี่ ไม่ได้อ่านจาก payload** — `isTopGifter` ของ connector ไม่มีในทุกเวอร์ชันและไม่ได้ใส่มาทุกอีเวนต์
และสิ่งที่ผู้ใช้ขอ ("ท็อป 3 ของไลฟ์") คือยอดสะสมทั้งเซสชัน ซึ่งมีแต่ตัวที่เฝ้าทั้งไลฟ์เท่านั้นที่รู้

## เอาขึ้นเกมที่ publish จริง

เซิร์ฟเวอร์จริงบน roblox.com **วิ่งมาที่ 127.0.0.1 ของเครื่องคุณไม่ได้** และท่อแบบ quick tunnel ก็ยังไม่พอ
เพราะมันแจก URL ใหม่ทุกครั้งที่เปิด ซึ่งหมายถึงต้องแก้ `TikTokConfig.Url` แล้ว **publish เกมใหม่ก่อนไลฟ์ทุกครั้ง**

ทางที่ใช้จริงคือ **Open Cloud MessagingService** — กลับทิศทางกัน สะพานเป็นฝ่ายส่งเข้าไป เกมแค่สมัครฟัง
จึงไม่มี URL อยู่ในเกมให้เก่า ไม่ต้องต่อท่อ ไม่ต้อง publish ซ้ำเวลาอะไรเปลี่ยน

### ทำครั้งเดียว

1. **publish เกม** (Studio → File → Publish to Roblox) ให้โค้ดชุดนี้ขึ้นไปอยู่ในเกมจริง
   — ไม่ทำข้อนี้ ในเกมจริงจะไม่มีไฟล์ `TikTokLive.server.lua` อยู่เลย
2. **เอา universe id** ของเกม (ไม่ใช่ place id) จาก create.roblox.com
3. **สร้าง API key** ที่ create.roblox.com → Credentials → API Keys → Create
   - Permissions: เพิ่ม `universe-messaging-service` ติ๊ก **publish** แล้วเลือกเกมนี้
   - Security: IP allowlist ใส่ `0.0.0.0/0` ถ้าไม่รู้ IP ตัวเอง
4. ก๊อป `live.env.example` เป็น **`live.env`** แล้วใส่สองค่านั้น (ไฟล์นี้ไม่ถูก commit)

### ทุกครั้งที่จะไลฟ์

ดับเบิลคลิก **`run-live.bat`** (ไม่ใช่ `run.bat`) → กดไปไลฟ์ใน TikTok → เข้าเกมจริง

`TikTokConfig.Mode` ปล่อยเป็น `"auto"` ไว้ได้: **Studio จะ poll เอง** (Open Cloud ส่งไม่ถึง Studio จึงพัฒนา/เทส
ด้วยทางนี้ไม่ได้) และ **เซิร์ฟเวอร์จริงจะ subscribe เอง** ตั้งเป็น `"poll"` หรือ `"push"` ได้ถ้าจะบังคับ

ถ้า push ล้มเหลว หน้าต่างสะพานจะบอกเหตุตรงๆ: `401/403` = คีย์ผิดหรือ IP ไม่อยู่ใน allowlist ·
`404` = ใส่ place id มาแทน universe id

**อีกทางถ้าไม่อยากใช้ Open Cloud:** ต่อท่อจริงที่มีชื่อโดเมนคงที่ (cloudflared named tunnel + โดเมนของตัวเอง)
แล้วตั้ง `Mode = "poll"` กับ `Url` เป็นโดเมนนั้น · **ต้องตั้ง `--key` ด้วย** ไม่งั้นใครรู้ URL ก็ยิงมอนเข้าเกมคุณได้

## ข้อที่รู้แล้วว่าจะสะดุด

- **`new TikTokLiveConnection(user)` พังทันที** ใน v2.4.4 options object ตัวที่สองไม่ใช่ของที่ใส่ก็ได้ —
  constructor อ่าน `options.processInitialData` ตรงๆ จึง throw ก่อนจะได้ลองต่อเลย ต้องส่ง `{}` เป็นน้อยสุด
  (ไฟล์นี้ส่ง `processInitialData: false` กัน TikTok โยนประวัติย้อนหลังมาทั้งกอง และ
  `enableExtendedGiftInfo: true` ให้ค่าเพชรของของขวัญติดมากับอีเวนต์)
- **ตัวเซ็นคำขอเป็นของนอก และต้องมีคีย์** connector v2 เซ็นทุกคำขอผ่าน `api.eulerstream.com` — ไม่มีคีย์ =
  ถูกปฏิเสธ · สมัครฟรี (Community $0 ตลอด 2,500 req/วัน) แล้วใส่ `TIKTOK_SIGN_KEY=` ใน `live.env`
- **"This endpoint requires a Business plan" ไม่ได้หมายความว่าต้องจ่าย $50** — และข้อความนี้กินเวลาไปมาก
  ตัวที่ต้องจ่ายจริงคือ **สองออปชันที่เราไม่ได้ใช้ผลลัพธ์เลย**:
  - `fetchRoomInfoOnConnect` ดึงชื่อห้อง/ยอดคนดู
  - `enableExtendedGiftInfo` ดึงตารางของขวัญ (ค่าเพชรติดมากับอีเวนต์อยู่แล้ว)

  ปิดทั้งคู่แล้ว **การเซ็นผ่านด้วยคีฟรีปกติ** · error ที่ได้ชี้ไปที่ `fetchWebcastSignatureFromEulerRoute`
  ทำให้อ่านเหมือน "การเซ็นต้องจ่ายเงิน" ซึ่งไม่จริง · เปิดกลับได้ด้วย `--room-info` / `--gift-info` ถ้ามีแพลนจ่ายเงิน
- **ราคาที่ปิดการเช็ค room info ไป:** connector จะไม่เช็คว่าบัญชีไลฟ์อยู่จริงก่อนต่อ → ห้องที่ไม่ได้ไลฟ์
  จะดูเหมือนต่อติดปกติ · มี watchdog เตือนให้ถ้าต่ออยู่ 3 นาทีแล้วไม่มีอีเวนต์เข้ามาเลย
- **ไลฟ์ที่จบแล้ว ไม่ใช่ไลฟ์ที่หลุด** ถ้าต่อใหม่ทุก 8 วิ มันจะต่อติด-ถูกบอกว่าจบ-หลุด วนไปเรื่อยๆ
  เผาโควตา Euler วันละ 2,500 หมดในไม่กี่ชั่วโมง · ไลฟ์ที่จบแล้วเว้น 60 วิต่อครั้ง (และยังบ่อยพอที่จะ
  **เปิดหน้าต่างค้างไว้ กดไปไลฟ์เมื่อไหร่ก็ต่อให้เอง**)

- **ชื่ออีเวนต์ "กดซับ" ไม่ใช่ `subscribe`** ใน connector v2 คือ `subNotify` — `WebcastEvent.SUBSCRIBE` อ่านได้ `undefined`
  ซึ่งเป็นวิธีที่ฟีเจอร์บอสจะไม่ทำงานเลยตอนไลฟ์จริงทั้งที่เทสผ่านหมด ไฟล์นี้ลงทะเบียนทั้งสองชื่อไว้แล้ว
- **รูปร่าง payload ยืนยันได้จากไลฟ์จริงเท่านั้น** connector เปลี่ยนชื่อฟิลด์ระหว่างเวอร์ชันหลักและซ้อนบางตัวไว้ใต้
  `gift` → ถ้าของขวัญมาแต่ `coins` เป็น 0 ให้รันด้วย `--dump` ดู payload จริงแล้วเติมชื่อฟิลด์ใน `onGift`
- **ของขวัญแบบกดรัว (`giftType === 1`)** ยิงอีเวนต์ทุกเฟรมที่ยังกดอยู่ ต้องรอ `repeatEnd` ถึงจะนับ
  ไม่รอ = หีบโผล่ทุกเฟรม
- **สะพานรีสตาร์ทกลางไลฟ์** ไอดีเริ่มที่ 1 ใหม่ แต่เกมถือเลขเก่าที่สูงกว่าอยู่ → เคยค้างไม่รับอะไรอีกเลย
  แก้ด้วย `session` token: เกมเห็นว่าคนละรันก็รับใหม่จาก `head` (**ไม่ย้อนเล่นคิวค้าง** — เปิดเซิร์ฟกลางไลฟ์
  แล้วเจอมอนสิบนาทีที่แล้วถล่มพร้อมกันคือสิ่งที่ไม่มีใครขอ)
